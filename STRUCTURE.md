# Project Structure Guide

A map of the AI Phishing Guard folder: what each file is, how the files call each other, and where to start reading. Use it to understand any single file in context.

## 1. The big picture

The project has two programs that work together.

| Program | Language | Runs where | Job |
| :--- | :--- | :--- | :--- |
| **Chrome extension** | JavaScript, HTML, CSS | Inside the browser | Watches pages, scores them, shows warnings |
| **Backend API** | Python (Flask) | On your computer, port 5000 | Predicts phishing probability from a URL with a trained model |

The extension works without the backend. The backend only adds the AI score.

```text
Browser                                        Your computer
┌──────────────────────────────────────┐       ┌──────────────────────────┐
│ background.js ──► content.js (page)  │       │  ml/app.py (Flask)       │
│      │                               │ HTTP  │    └─ feature_extractor  │
│      └──────── shared/api.js ────────┼──────►│    └─ model/*.pkl        │
│ popup / options / warning / history  │       └──────────────────────────┘
└──────────────────────────────────────┘
```

## 3. Extension files in detail

### `manifest.json`
Declares everything Chrome needs: the permissions, the service worker (`background.js`), the popup, the options page, and which scripts are injected into pages (`shared/config.js`, `shared/scoring.js`, `content.js`). Start here to see what runs and when.

### `background.js` (the controller)
Runs without a window. It:
- listens for page navigation and page load,
- calls the three detectors and fuses the scores,
- decides whether to block, and opens `warning.html`,
- stores tab results and history,
- answers messages from the popup and warning page.

Loads `shared/*.js` with `importScripts`.

### `content.js` (inside the page)
Has two jobs: analyse the page structure when asked, and draw the badge or banner. It only reads structure (forms, links, iframes, title). It never reads typed text.

### `shared/` (logic used in more than one place)
| File | What it holds | Used by |
| :--- | :--- | :--- |
| `config.json` | The single list of keywords, brands, TLDs, thresholds, trusted domains | Python and JavaScript |
| `config.js` | The same data as a script. Generated by `tools/sync_config.py` | Extension, tests |
| `scoring.js` | `analyzeURL`, `calculateCombinedScore`, `classify`, `trustStatus`, brand detection | background, popup, content, tests |
| `settings.js` | Load, validate and save user settings | background, popup, options, warning |
| `api.js` | `predict`, `health`, `modelInfo` calls with timeouts and a 60 s cache | background, popup, options |

### UI pages
| Page | Opened by | Talks to |
| :--- | :--- | :--- |
| `popup.*` | Toolbar icon | background (messages), content (analysis), backend (via `api.js`) |
| `options.*` | Popup Settings button | `settings.js`, `api.js` |
| `warning.*` | background redirects a dangerous tab to it | background (proceed, trust, go back) |
| `history.*`, `dashboard.*` | Popup buttons | Read `chrome.storage.local` only |

## 4. Backend files in detail

| File | Purpose | Reads | Writes |
| :--- | :--- | :--- | :--- |
| `app.py` | HTTP API. Loads the model at startup and refuses a mismatching feature list | `model/phishing_model.pkl`, `evaluation_results.json` | nothing |
| `feature_extractor.py` | `extract_features(url)` returns 32 numbers in a fixed order | `shared/config.json` | nothing |
| `build_dataset.py` | Downloads PhishTank and Tranco, builds labelled URLs | the internet | `dataset/phishing_urls_full.csv`, `DATASET-INFO.json` |
| `dataset_utils.py` | Cleaning and the domain-grouped train/test split | CSV | nothing |
| `train_model.py` | Compares two models, trains the best, then calls the evaluator | dataset | `model/phishing_model.pkl` |
| `evaluate_model.py` | Held-out metrics and report | model, dataset | `evaluation_results.json`, `MODEL-EVALUATION-REPORT.md` |
| `domain_intel.py` | Domain age (RDAP) and certificate check, off by default | internet | nothing |
| `predict.py` | Run one URL from the command line | model | nothing |

API endpoints: `POST /predict`, `GET /health`, `GET /model-info`, `GET /api/model-evaluation`, `GET /test-pages/...`.

## 5. How a page scan flows through the files

1. You open a site. Chrome loads `content.js` into it (from `manifest.json`).
2. `background.js` sees the navigation and calls `Scoring.analyzeURL` in `shared/scoring.js`.
3. It asks `content.js` for page analysis with the `ANALYZE_PAGE` message.
4. It calls `AIPhishApi.predict` in `shared/api.js`, which posts to `ml/app.py`.
5. `app.py` calls `extract_features` and the model, and returns a probability.
6. `calculateCombinedScore` fuses the three scores and picks SAFE, SUSPICIOUS or DANGEROUS.
7. `background.js` saves history, then either sends `SHOW_WARNING` to `content.js` or redirects to `warning.html`.
8. The popup later asks `background.js` for the stored result and shows the report.

## 6. Where data is stored

| Data | Location | Written by |
| :--- | :--- | :--- |
| Scan history (max 100) | `chrome.storage.local` key `aiphish_scan_history` | background |
| Settings and trusted sites | `chrome.storage.sync` key `aiphish_settings` | `settings.js` |
| Tab results, proceed choices | `chrome.storage.session` | background |
| Trained model | `ml/model/phishing_model.pkl` | `train_model.py` |
| Training data | `ml/dataset/` | `build_dataset.py` |

## 8. Rules that tie the files together

- **One list, two languages.** Keywords, brands and TLDs are only edited in `shared/config.json`. Run `python tools/sync_config.py` afterwards. A test fails if `config.js` is stale.
- **Feature order is a contract.** If `FEATURE_NAMES` in `feature_extractor.py` changes, the model must be retrained, or `app.py` will refuse to start.
- **Scores are decided once.** Only `background.js` classifies a page. `content.js` and the popup display the `statusLevel` they receive.
- **JavaScript and Python must agree.** `tests/unit/parity.test.js` compares brand detection in both languages.

## 9. Suggested reading order for a newcomer

1. `README.md` for the overview.
2. `manifest.json` for the entry points.
3. `shared/config.json` for the rules in plain data.
4. `shared/scoring.js` for how scores are made.
5. `background.js` for the flow.
6. `content.js` and `popup.js` for what the user sees.
7. `ml/feature_extractor.py` and `ml/app.py` for the AI side.
8. `tests/` to see the expected behaviour as examples.
